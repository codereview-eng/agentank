# 对战页「策略文本优先」重设计（strategy-first）

> 方向（用户拍板）：战斗 UI 隐藏脚本细节，相应区域显示该坦克**策略的文本描述**；
> 玩家第一优先是改策略文本，点「AI 生成脚本」调 SDK 的 LLM 能力生成代码；
> 只有点开隐藏的脚本窗口，才能直接修改坦克代码。
> 设计原则（一句话）：**你当教练，用中文布置战术；写代码这件事交给 AI，想抠细节再掀开引擎盖。**

## 技术可行性（2026-08-13 调研实证）

- 平台 Play SDK v1（`__sdk/v1.js`）原生带 LLM 能力：`const { text } = await play.llm.chat(prompt)`，
  单 `await` 隐藏 202 accept-and-poll；错误统一 `PlayError {code,message,hint}`。
- 开启方式：`schema.json` 顶层声明 `"llm": {"enabled": true}`（线上 403 `LLM_DISABLED` 探针 +
  生产 `llm.mjs` `normalizeLlm` 源码双重实证；只允许 `enabled`/`requireAuth` 两键，多余键 CONTRACT_VIOLATION）。
  LLM 花销走玩家自己的平台配额，游戏侧零密钥。
- `requireAuth` 缺省 true：**匿名玩家不能调 LLM** → 必须有降级路径。

## 交互设计（左栏改造）

```
┌ 左栏「战术指挥」 ─────────────────┐
│ 📝 策略描述（textarea，自然语言）      │  ← 默认视图，第一优先
│    「贴脸抢星，血量低于30%就传送跑」    │
│ [⚡ AI 生成脚本]  [状态行：生成中…]    │
│ ▸ 查看/编辑脚本（默认折叠 <details>）  │  ← 掀开引擎盖才见代码
│    #editor（原编辑器整体移入）        │
│ （对手/技能/地图/开战/保存/车库 照旧）  │
└──────────────────────────────┘
```

- **策略描述区**：每台坦克一份 `strategy` 文本；切车库/登录衔接时跟随坦克。
- **⚡ AI 生成脚本**：prompt = 引擎 API 契约摘要（`decide(api)`、可用动作、当前装备技能）+ 玩家策略文本；
  返回文本 → 提取代码块 → `compileScript` 校验 → 通过才写入脚本区并提示「已生成，可开战」；
  编译失败自动带错误重试一次，再失败如实报错（fail-closed，不静默塞坏代码）。
- **脚本窗口**：默认折叠；点开可直接改（能力保留，零回归）；手改后策略文本标注「代码已手工修改」。
- **降级路径**（fail-closed 逐级）：
  1. 未登录/SDK 不可用 → 生成按钮变「登录后可用 AI 生成」，点击引导 `play.login()`；脚本窗口照常可手改；
  2. `LLM_QUOTA_EXCEEDED` → 按 `err.hint` 展示配额提示；`LLM_TIMEOUT` → 提示可重试；其余码原样透传 hint；
  3. LLM 全不可用 → 与现状完全一致（默认模板 + 手写代码），零回归。
- **存储**：`schema.json` Tank 实体加 `strategy: "string"`；本地存档 `agentank.save` 的 tanks[] 条目加 `strategy`（迁移兼容：缺省空串）。

## Spike 验证口径（先证收益再全面实现）

1. **prompt 合同 spike**：策略文本 → LLM 输出样例 → 代码提取 → `compileScript` → 引擎真跑一局，
   全链路 PASS 才算 prompt 设计可行（`eval/` 下落 spike 脚本 + 样例）。
2. **交互收益 spike**：默认视图认知负担对比（可见代码字符数 ~1.2k → 0；新手首个可操作动作
   「读懂 JS 写代码」→「写一句中文点按钮」）；dist 体积增量在预算内；现有测试零回归。

## 明确不做

- 不自动开战、不自动保存生成结果（玩家确认后才落库）；
- 不在游戏侧存任何模型密钥（平台网关代付，玩家配额）；
- 本轮只 PR til merge，不部署（部署照发布手册另走）。
